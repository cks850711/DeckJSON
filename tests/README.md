# 測試

DeckJSON 以**夾具式驗收測試**為主，而非單元測試。本工具的正確性標準是「匯出的 `.pptx` 有沒有如實呈現」——那是端到端的性質，用一份刻意涵蓋各類元素的簡報產生 pptx、再逐項驗證產物，比拆開驗個別函式更貼近真正要保證的事。

## 方法

| 腳本                | 驗什麼                                  |
| ----------------- | ------------------------------------ |
| `make_fixture.py` | 產生驗收測試簿：一份涵蓋各類元素與邊界情況的 `.deck`       |
| `verify_pptx.py`  | 解開匯出的 `.pptx`，逐項比對 OOXML 結構與數值       |
| `check-deck.py`   | 靜態檢查 `.deck` 的常見錯誤（顏色格式、缺漏欄位、不合法列舉值） |
| `dj-smoke.js`     | 腳本介面 `window.DJ` 的冒煙測試：每個動詞呼叫一次，只經由 `DJ` 與畫布 DOM 驗證（已公開，在瀏覽器 console 執行） |
| `dj-autosave.js`  | 自動存檔還原：型別不認得的元素還原得回來、存檔與匯出前後都在；還原失敗時，之後的編輯與「開新簡報」不會蓋掉原記錄（已公開；在開發伺服器上任一非 DeckJSON 頁面的 console 執行，頁面放在 iframe 裡載入，見檔頭） |
| `server-test.js`  | `deckjson-server.js` 的測試：真的啟動伺服器、送 HTTP，驗證 port 分配、來源限制、寫入範圍、修改時間檢查與閒置結束（已公開，`node tests/server-test.js`） |
| `host-smoke.js`   | 由 `deckjson-server.js` 提供時的冒煙測試：`?open=`、`DJ.save()` 改走伺服器、`save({as})`、分頁回報（已公開；把它複製到一個空資料夾、用該資料夾啟動伺服器，在頁面 console 執行，見檔頭）。DJ App 的槽位要兩個視窗，手動驗：同一格在第二個視窗顯示「其他視窗使用中」、關掉第一個視窗後自動變回可選、重新整理留在原槽位 |

`verify_pptx.py` 的輸出是純文字，所以重構時只要比對前後兩份輸出是否**逐字一致**，就知道有沒有動到匯出語義。這是改動內部結構（而非功能）時最可靠的護欄——例如更換儲存格式、重排程式碼，匯出結果都應該零差異。

## 公開狀態

目前的夾具內含未公開的簡報內容，因此素材與腳本尚未隨 repo 發佈。最小化的合成夾具會陸續放進本資料夾。
